# GLYPH ASCII Studio

安装：`npm ci`

本地启动：`npm run dev`

类型检查：`npm run typecheck`

单元/集成测试：`npm test`（Node 内置 test runner + esbuild，共 26 个用例）

Docker 启动：`docker compose up --build`，访问 http://localhost:18018。

## 字节预算模式

在 CHARACTER LAB 面板可切换两种尺寸控制方式：

- **列数模式（默认）**：沿用原有行为，密度只控制列数，行列换算与输出结果与旧版完全一致。
- **字节预算模式**：以最终 UTF-8 文本文件的字节预算为准，重新分配可用字符数与行列。

### 为什么不能按字符个数估算

字符集允许包含中文（显示占 2 格、UTF-8 占 3 字节）与组合符（显示 0 格、占 2~3 字节），
**显示宽度与编码字节数是两套度量**。容量计算全部走真实编码度量（`shared/metrics.ts`），
绝不把字符个数当作文件大小。

### 工作流程

1. **生成前估计**：面板实时展示保守预算估计——按字符集中「最大单字字节」估算，
   并计入换行约定（LF = 1 字节，CRLF = 2 字节），因此估计永远 ≥ 真实结果，不会先承诺后超限。
2. **两种取舍策略**
   - 保完整轮廓：优先保住单元格数量（画面分辨率），预算不足时均匀压缩灰阶层级；
   - 保局部灰阶：字符集一个不砍，通过缩小画面满足预算。
3. **生成后核验**：按真实 UTF-8 编码重新计算字节数，展示实际占用、字符净字节、
   换行开销、单字峰值/均值字节与余量。若核验超限直接报错拒绝输出，**绝不截断末尾假装成功**。
4. **预览即设备视图**：画布按真实显示占位渲染（宽字符双格、组合符附着零格），
   可开启「损失分布」热力叠加，层级损失 / 尺寸损失 / 量化损失分别量化展示。
5. **下载绑定确定布局**：.TXT 与 .PNG 都来自同一个 grid 与同一份换行约定，
   下载前再次用真实编码核验；复制剪贴板走同一套校验。
6. **预算过小**：当预算连 1×1 最小画面都放不下时，面板给出当前字符集与换行约定下
   可实现的字节下界，抛错并保留上一份成功作品，旧输出不会被覆盖。
